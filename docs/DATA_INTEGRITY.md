# 资料故障与恢复边界

更新：2026-10-24（Asia/Shanghai）。这是 Alpha.2 开发分支的源码与本地验证记录，不改变已发布的 Alpha.1 tag，也不是原生安装、全部磁盘故障或真人试用验收。

## 先复现，再修复

此前测试覆盖了无效输入不误删图，但没有覆盖图片操作已经发生、资料提交随后失败的情况。新增的首轮 7 项负向测试全部失败，确认了以下问题，而不是根据代码猜测后直接宣称安全：

| 旧行为 | 后果 | 本轮修复 |
| ------ | ---- | -------- |
| 删图、禁止截图或移除记录先删除 PNG，再保存资料 | 保存失败时内存回滚，但原图已经消失 | 资料先提交，之后才清理不再引用的图 |
| 重新截图直接替换原 PNG，再保存时间戳 | 保存失败时原时间戳对应新图片 | 每次生成独立图片版本，提交前不覆盖旧图 |
| 恢复提交成功后的清理错误继续抛出 | 界面说恢复失败，实际已换库 | 区分提交失败与提交后清理未完成，返回已提交库和明确警告 |
| 启动的整个加载 / 保存过程统一忽略 ENOENT | 加载成功之后的写入失败被误认成空库 | 仅最初读取不存在时使用新库；后续失败正常拒绝启动 |
| 截图仅在导航前复核身份 | 截图过程中换 owner 仍可能覆盖旧卡封面 | 截图后再次核对已存身份及本次截图前得到的证据 |

## 当前提交协议

- 新图片使用独立的 `项目 UUID.图片版本 UUID.png`，独占创建、权限 0600；写入完成并同步后，才将版本引用加入候选资料。
- `library.json.tmp` 写入并同步、权限收紧为 0600 后，以同目录 rename 提交到 `library.json`。这是本轮定义的资料提交点。
- 提交前任一失败保留原资料和原图，只清理本次操作创建的文件；图片写了一部分也在追踪范围内。清理又失败时保留原始错误，不让次要错误掩盖它。
- 提交后不伪装回滚：内存和接口继续显示已提交结果，再尝试删除旧图 / 临时图。清理失败返回 `storageCleanupPending` 与不含路径的文件系统错误码。
- Web 主界面和业务面板显示中英文自有警告，明确图片可能仍留磁盘、不再提供这些未引用图片、清理完成前不要分享资料目录。不会同时显示“全部图片已删除”。可使用受会话令牌保护的重试按钮；重试本身不要求重新写元数据。
- 下一次启动按有效资料中的引用收集孤立图片；权限仍不允许删除时继续警告，不偷偷恢复已经关闭的许可。不存在隐藏的永久旧图备份。
- GET 资料库、封面与用量读取已提交快照，不向另一窗口泄露正在恢复 / 编辑、之后还可能失败的中间状态。变更仍排队，前一个失败不会阻断后续操作。
- `before-restore.json` 同样先写临时文件再原子替换，始终仅含元数据，不保留图片内容或图片版本引用。失败不会先覆盖上一次完整检查点。

## 资料版本与回退

开发源码的本地资料格式为 **v3**，软件包版本仍为 `0.3.0-alpha.1`，两者不是同一个版本号，也不表示已经发布 Alpha.2。

- 读取 v1 / v2 时，先完整保留一次对应的 `library.v1.backup.json` / `library.v2.backup.json`，不覆盖既有副本。副本通过完整临时写入后无覆盖地建立；部分写入不会被认可为完成。已有副本损坏时拒绝继续，而不是覆盖它或清理原图。
- 旧的 `项目 UUID.png` 不改名；尚未重新截图的封面继续使用原文件。用户命名、收藏、关联、许可等字段不因格式迁移改变。
- **不要直接用旧 Alpha.1 源码打开 v3 资料目录。** 旧代码会拒绝不支持的版本，不是可直接降级的兼容读写。只复制迁移前 JSON 也不能保证恢复历史封面：后续明确删图 / 重新截图时，旧图片可能已清理。
- 需要回到旧代码时，先从新版本显式导出需要的备份，再在独立的空资料目录用旧版本恢复。导出仍是原 `locade-backup` 容器版本 1、内含 v2 状态，图片按项目 ID 打包，不依赖本地版本文件名；旧版备份也可由新代码恢复。导出图片需明确勾选，备份本身可能含秘密。
- 原生 App / DMG 不重建、不覆盖，也不指向新目录试跑。源码更新不是原生升级验收。

代码提交 `882d1806d09d14a6162f7249697757f9908ae315` 的 [PR #7 CI](https://github.com/opszn/locade/actions/runs/39986534011) 三组均实际通过，各 118 / 17 / 7；它是依赖 #6 的独立增量，尚未合入或发布。后续提交必须看自己的检查结果。

原始失败日志、后续全量日志、隔离截图与真实库 / 原生身份保留基线均在本机忽略提交的 `test-results/alpha2-data-integrity/`，不公开个人目录、原图、资料或令牌。旧测试若写死 `UUID.png`，已改为读取实际图片引用，仍检查旧图被保留或清理；不是删掉安全断言来获得通过。

## 不应推导的保证

- ENOSPC / EIO 是确定性注入，不是实际耗尽磁盘或损坏存储设备；权限测试则使用真实受控目录。
- SIGKILL 是进程中断，不是断电。没有穷举所有系统调用、文件系统、存储缓存损坏、磁盘断连或目录同步失败，不能声称断电级 ACID 或所有 I/O 可回滚。
- 检查前后仍有瞬时窗口；owner 在中间变更又变回、完全匿名页面或页面自身内容变化无法由这些证据完全识别。不是恶意页面沙箱。
- 当前只测试匹配 Chromium 与 macOS；不等于所有干净机器、跨平台或原生 UI。没有新增下载器、自动项目执行或遥测。
- 陌生使用者首次安装与真实一周使用仍待参与者完成，自动故障注入不能替代。
