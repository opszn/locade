# 站内动作与反馈验收

本文保留交互整改阶段的 68 核心 / 10 浏览器结果。后续公共双源与 5 项发布护栏已完成三组核心 73 / 浏览器 10 / 系统发现 7 回归，当前状态和指纹见 [发布清单](RELEASE_STATUS.md)；不要将下方历史指纹当成当前源码或已打包原生。

更新：2026-10-22。用户实际截图指出批量忽略使用浏览器确认框，要求站内动作由 Locade 自己承载。本轮是体验缺陷修复，不是扩展产品范围。

## 为什么之前没有挡住

之前测试确实点过忽略 / 取消 / 确认，但测试用 Playwright 的 `dialog.accept()` / `dismiss()` 接受浏览器 `confirm`，只检查资料变更是否正确，没有检查“确认是否属于 Locade 自己的界面”。这是验收标准缺漏，不能用过去 8/8 通过解释为体验合格。

本次查出 **8 处原生确认调用**（恢复备份原先连续两次确认），全部移除；同时补齐单项忽略、单张删图和更改目录可能删封面的确认。统一覆盖下面 **10 类站内决策**。

## 统一规则

- 确认使用 Locade 渲染的站内弹层；HTML `dialog` 只提供顶层 / 惰性背景基础，内容、样式、焦点、取消和提交均由应用维护，不再调用 `alert` / `confirm` / `prompt`。
- 默认聚焦取消；取消、关闭、Escape 不发送资料变更；Tab / Shift+Tab 在确认框内循环，关闭后返回原操作位置。确认框存在时自动发现暂停。
- 操作按钮说明实际行为，不只写“确定”；涉及记录时显示名称、短 ID、目录和地址，说明删除 / 保留 / 可恢复的边界。长内容在弹层内滚动，标题和操作按钮保持可见。
- 站内表单关闭浏览器原生校验气泡，由页面显示校验、请求进度、成功或错误；截图用量读取失败不再静默当作 0，可在站内重试。
- 备份恢复默认不恢复图片；“取消”只取消，不能再兼任“仅恢复元数据”。图片恢复必须在站内明确勾选。备份 / 恢复执行期间，即使关闭设置，其他资料变更仍禁用。
- 打开项目的身份门控失败，浏览器新页显示 Locade 品牌与返回项目库入口，不再给人工导航显示裸 JSON；普通 API 请求仍保持 JSON 错误协议。

## 十类确认

| 动作 | 站内确认内容 | 验证 |
| --- | --- | --- |
| 同名记录批量忽略 | 逐条核对所选 ID / 目录 / 地址；只隐藏、不合并 / 转移图片 / 停服务，可撤销 | 取消 / Escape / 默认 Enter 不写入；确认 / 撤销 / 冲突；真实页面只读取消 |
| 单项忽略 | 明确移至已忽略，保留记录、图片与收藏，可恢复 | 取消与确认、恢复 |
| 从库移除 | 删除记录与截图，不删项目目录，不停止服务，可能重新发现 | 取消保留记录 / PNG；确认删除 |
| 单张截图删除 | 仅删除当前卡片封面，项目与目录保留，不可撤销 | 取消 PNG 字节保留；确认删除 |
| 关闭全局截图 | 禁止截图并删除全部已存封面，保留项目资料 | 取消开关 / PNG 保留；确认关闭 / 删除 |
| 禁止某项目截图 | 仅该项目禁用并删封面，不改变全局许可 | 取消 / 确认与开关 / 封面校验 |
| 清空全部截图 | 显示用量，不关闭截图许可，不影响外部导出的备份 | 取消 / 确认、删除后许可保留 |
| 关联到不同目录且有封面 | 显示旧记录与新目录，说明目录改变可能删除封面 | 取消目录 / PNG 不变；确认改目录 / 删除旧封面 |
| 解除目录关联 | 清除目录身份与封面，说明后续发现可能重新关联 | 取消 / 确认 |
| 备份替换恢复 | 显示文件名、替换风险、元数据恢复副本；独立图片选项默认不勾选 | 取消 / Escape 不恢复；再次打开重置勾选；仅元数据 / 带图恢复；超限 / 坏文件拒绝 |

## 其他现有动作

| 范围 | 反馈与边界 | 验证方式 |
| --- | --- | --- |
| 添加地址、重命名、目录输入 | 站内字段 / 接口错误；无效 URL / 空名称 / 非绝对路径不使用浏览器气泡 | 新交互回归 + 原 API / UI |
| 搜索、分类、收藏 / 最近、重开核对 | 在页面展示结果 / 状态；核对重开不沿用旧勾选 | 原 UI 与五项目流程 |
| 发现、截图、目录 / 编辑器打开 | 按钮忙碌状态、站内错误 / 成功提示，不自动运行项目脚本 | 原 UI、真实 PNG、系统发现；编辑器仅验证意图，不真的拉起用户 IDE |
| 备份下载、恢复 | 下载交接提示、错误反馈、全局忙碌保护；不冒称浏览器已把文件写入目标磁盘 | 真实下载 / 备份恢复；受控失败，关闭设置后错误仍可见 |
| 用量 / 权限 / 自动发现 | 用量失败可重试；权限变更明确确认；前台定时发现按已有规则暂停 | 新存储失败 / 重试 + 原计时 UI |
| 打开项目失败 | 自有错误页、转义不可信消息、返回入口 | 核心转义测试；真实 Chromium 旧窗口左 / 中键，桌面 / 320px 页面检查 |

**系统集成的边界**：选择本机备份文件仍须系统文件选择器；下载目标 / 浏览器权限仍由浏览器决定；打开项目网页、Finder / 编辑器、macOS 登录项批准属于显式系统集成。Locade 提供入口和站内决策，但不伪造文件权限、不自制文件系统沙箱，也不能控制被打开的其他项目自己的弹窗。macOS 原生菜单栏实际视觉交互仍未通过，不借本轮 Web 回归宣称已验收。

## 实际结果

- 最新核心 Node 26.7.0 / 官方 Node 24.22.0 各 **68/68**：原 66 + 站内交互源码规则、打开失败页转义 2 项。
- 完整 Chromium **10/10 连续两轮**：原 8 更新为点击站内确认，新增 2 个动作 / 反馈流程；所有应用浏览器测试都监听并拒绝原生弹窗，不再接受原生确认来通过测试。
- 新流程覆盖 1440 / 390 / 320px（手机含 640px 短视口）、滚动到最后记录、操作按钮可见、取消 / Escape / 默认 Enter、正反 Tab / 焦点恢复、10 类决策及图片许可、无效字段 / 文件、存储重试、导出失败和执行期间其他操作禁用。
- 首轮新增测试抓到 Tab 末尾会离开弹窗，修复焦点循环后通过；另一轮测试对 macOS `/var` / `/private/var` 路径别名的预期不正确，改成真实规范化路径，没有修改身份逻辑来迁就测试。失败日志保留。
- 当前源码系统发现两个 Node 各 **7/7**、完整清理，五项目 **10/10**；格式检查通过。系统测试仍限自有 PID 与已知随机路径，不是完整冷扫描或真人找回实验。
