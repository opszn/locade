## 用户反馈：同名卡片不是已解决的日用体验

只读排查时，「某个本地工作台」确有 4 张卡片，当时 1 张在线：2 张旧版无目录 / 进程证据记录，另 2 张分别关联仓库根目录和 frontend 子目录。它们不是 4 个已确认的在线项目；不同目录也不能只凭同名断言同一服务。

旧记录保留有防止错误合并的原因，但此前缺少区分和整理流程，是产品缺口。没有自动清除用户旧卡片或图片，也没有把旧封面移给某个新进程。新增「同名待核对」只用于比较，默认不勾选；用户确认后将所选记录移至「已忽略」，可撤销或逐条恢复。图片仍留本机并占用空间，删除图片仍需单独操作。

## 这次实际发现并修复

| 问题                 | 可复现场景                                                        | 修复与验证                                                                                                  |
| -------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 卡片持续增长         | 同 URL 的强身份结果与整组元数据缺失交替，6 次循环由 1 张增至 7 张 | 无证据响应不另立新项目；已知卡保留身份和封面但标未确认；循环及换 owner 护栏测试                             |
| 补全目录也重复       | URL 规范化相同、进程 observation 相同，仅 identity 从空变为目录   | 凭原进程证据补全原卡，保留 UUID / 名称 / 收藏 / 封面；不升级无 observation 的旧卡                           |
| 绑定别名绕过重复保护 | 两卡 URL 分别为 localhost 和 127.0.0.1，再绑定同目录              | 绑定比较规范化 URL，冲突拒绝；不以此自动合并                                                                |
| 旧窗口仍能误开       | 第二窗口已确认端口换 owner，第一个窗口还持有旧 href               | 卡片走本机打开路由；服务端先挡已知复用，再检查当前页面，成功才跳转并记最近访问；真实 Chromium 左 / 中键回归 |
| 失败设置已删图片     | PATCH 同时请求禁止截图和空名称，接口 400，但 PNG 已被删除         | 所有字段先校验，再执行删除；API 验证原 PNG / 元数据不变、带图备份仍可用                                     |

另新增批量忽略的并发防护：每条所选记录携带比较凭据，全部验证后在单个事务中变更；任一所选记录变化则整批拒绝。撤销也验证当时返回的凭据，不覆盖后续收藏、名称、地址或截图改动。频繁刷新时间不参与凭据，但身份、在线状态和所选记录实际内容变化会参与。

## 尚不能保证

- 同名并非同一作品；同目录多角色同时重启后若所有进程证据都变了，仍可能保守保留新卡。已忽略的 UUID 不是标题 / 端口黑名单，不承诺永不新增。
- 完全没有 owner 证据的匿名卡仍可按现有成功 HTML / 标题规则使用，不能说强身份已确认。已保存的 observation 丢失 / 变化则拒绝截图和跳转，已知复用标记不能靠同标题解除。
- 复核与浏览器真正访问之间仍有时间窗口；不是恶意页面沙箱或所有瞬时竞争的证明。打开项目新增实际探测 GET，也可能受超时、鉴权、重定向、自签名 HTTPS 限制。
- 本次覆盖了无效参数导致的图片误删，尚未完成磁盘满、权限中途变化、任意文件 I/O 故障、每个崩溃时机的全面注入；不能把内存事务回滚视为所有图片操作都可回滚。
- 真实系统测试使用自有 PID 白名单和已知随机路径，不是完整冷扫描。浏览器整理测试的封面是合成 PNG，不是用户截图；旧窗口测试使用真实浏览器 / 网页，但身份元数据为注入。
- 最新打开路由和整理功能已进入独立候选包，菜单栏打开也改用 `/open/:id`；编译和源码一致性通过，不等于实际菜单点击验证。新候选原生首次 SIGKILL，附着跳过；默认旧包 / 固定副本未覆盖，旧原生测试结果不能沿用。视觉 UI、干净机器分发仍未通过。
- 没有一周真实留存、真人找回效率或竞品实测结论。用户此前实际试用和正向截图反馈成立，但不是这些结论的替代。
